Goal

CI is the one layer that works for every agent. It doesn’t need a hook inside the tool, so it covers agents and editors that have none, such as GitHub Copilot, Cursor and JetBrains IDEs, and changes people make by hand. The cost is timing: it finds a violation after the file is written, when the pull request runs.

The example decision is ADR-001, an architecture decision record (ADR) that bans the Celery library. Each guide in this section uses it.

Prerequisites

  • A decision with an activated rule, committed in .mneme/project_memory.json, the memory file Mneme compiles your decisions into. A decision imported without any rule blocks nothing. Steps 1 to 7 of the Claude Code setup do this for ADR-001 with no agent involved; Install Mneme and activate your first protection explains each command.
  • Your ADRs in docs/adr/, committed with Unix (LF) line endings: add docs/adr/*.md text eol=lf to .gitattributes. The memory file records a hash of each ADR’s bytes.
  • Permission to add a workflow and to require it before merge.

Tested versions: mneme-hq 0.11.0. We ran each job’s check script against a local copy of a pull request (bash for GitHub Actions, sh -e for GitLab CI), not on hosted runners.

GitHub Actions

Save this as .github/workflows/mneme-decisions.yml. Fail a pull request that breaks an ADR explains it line by line.


    
The workflow does two things. It re-imports the ADRs and fails if that changes the memory file, which means someone edited an ADR without re-importing it. Then it runs mneme check on each added or modified text file, keeps the worst exit code, and uploads every JSON verdict.

    
To block merging, add a branch ruleset for main with “Require status checks to pass” and select the mneme job.

What is and isn’t enforced

    
    
      
  • Covered: every text file a pull request adds or modifies, checked whole, in the repositories and branches where you require the job.
    • 
      
  • After the fact: the file is already written and committed. Nothing stops an agent while it works; an agent hook does that, where the agent has one.
    • 
      
  • Not covered: decisions imported with no rule, deleted files, binary files, pushes that skip pull requests, and branches where the check isn’t required.
    • 
      
  • Whole files: a file that already broke a decision fails as soon as someone touches it.
    • 
      
  • The check can be weakened. An agent that can edit the ADRs, the memory file or this workflow can change what the check enforces. Protect them with code owners and required review, as the how-to guide describes.
    • 
    

  


  

    
Troubleshooting

    
The memory check fails after an ADR edit

    
The ADR changed but the committed memory file didn’t. Re-import locally and commit the result:

    
mneme adr import docs/adr --memory .mneme/project_memory.json --apply --update-existing

    
If you edited an ADR whose rule you activated, the import refuses rather than drop that rule silently, and names the flag to pass. The install how-to shows the message and the fix.

    
The memory check fails on every pull request

    
Check the ADRs’ line endings. Add docs/adr/*.md text eol=lf to .gitattributes.

    
The check step fails before checking any file

    
The checkout is shallow, so git can’t compare against the base branch. Keep fetch-depth: 0 on GitHub, or GIT_DEPTH: "0" on GitLab.

    
You want findings without failing pull requests yet

    
Add --mode warn to the mneme check line. Verdicts still print, but WARN and FAIL exit 0:

    

    
That output exited 0. Remove the flag once the findings look right.
