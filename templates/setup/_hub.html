The three layers

Each layer does one job. Two of them enforce your decisions; the third helps an agent find them. You can start with any one, and the guides add the others.

  • DiscoverOptional

    Decision MCP server

    A local server that speaks the Model Context Protocol (MCP), so an agent can search decisions, ask which ones apply to a file, and propose new ones for people to review. It blocks nothing.

  • EnforceCore

    Mneme command-line interface (CLI) and agent hook

    The mneme command runs the checks. A hook is a command your coding agent runs before it edits a file; Mneme’s hook blocks an edit that breaks an active rule. Coverage differs by agent.

  • VerifyCore

    CI check before merge

    A job in your pipeline runs mneme check on each file a pull request adds or modifies. It catches changes the hook missed, and changes from agents and people with no hook.

What you install

The architecture decisions live in your repository, in a decision record (ADR) folder and a memory file Mneme compiles from it. Every layer reads that one file.

What no setup guarantees

Check one allowed change and one blocked change in your own repository before you rely on any layer. Every guide shows both. Three limits apply everywhere:

  • Hooks fail open. If a check crashes or times out, the Claude Code hook allows the edit, and the Codex CLI hook marks it unevaluated without blocking.
  • Some writes are not intercepted before they land. Most shell commands and scripts reach disk first; Claude Code and Codex CLI check them when the agent ends its turn, and other agents rely on CI.
  • CI covers only what your pipeline runs on: the files a change adds or modifies, in the repositories and branches where the job is required.
