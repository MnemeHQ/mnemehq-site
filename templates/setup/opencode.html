Goal

OpenCode is an open-source coding agent that runs in a terminal, an editor extension and a desktop app. Mneme has no released hook for it. What exists is an experimental adapter for the terminal CLI, which is not in any published mneme-hq release. So this setup puts the weight on CI and treats the adapter as optional and unproven.

The example decision is ADR-001, an architecture decision record (ADR) that bans the Celery library.

Prerequisites

  • A git repository with ADR-001 activated: steps 1 to 3 of the Claude Code setup, which need no agent.
  • Permission to add a CI workflow and make it a required check.
  • For the adapter only: OpenCode 2.3.0, the version the adapter was validated on, and a Python codebase.

Tested versions: the CI check ran against mneme-hq 0.11.0, on a local copy of a pull request. We did not run OpenCode or the adapter for this guide.

Configure

1. Add the required CI check

Copy the GitHub Actions workflow or GitLab CI job, commit it with the ADR and the memory file, and make it a required check. This is the layer that enforces ADR-001 on OpenCode’s changes.

2. Optional: give OpenCode the decisions

If your OpenCode setup can start local Model Context Protocol (MCP) servers, register Mneme’s decision server so the agent can look decisions up before it writes. The decision MCP setup has the command and arguments. We have not tested it inside OpenCode.

Experimental adapter

    
Experimental. Merged on Mneme’s main branch on November 18, 2026, after the 0.11.0 release, and not a supported integration. Installing mneme-hq 0.11.0 does not include it.

    
The adapter is a plugin for OpenCode’s tool hook in the terminal CLI. In strict mode it makes OpenCode refuse two operations when they break a FORBID_LITERAL rule: writing a new .py file, and editing an existing one, where only the added text is checked.

    
To evaluate it, you need Mneme’s source at the main branch, both for the plugin in integrations/opencode-plugin and for the Python code it calls. The plugin’s README.md configures it in opencode.json with an absolute authorityPath:

    
{
  "plugins": [
    {
      "package": "/path/to/mneme/integrations/opencode-plugin",
      "options": {
        "authorityPath": "/path/to/authority.json",
        "timeoutMs": 60000
      }
    }
  ]
}

    
authority.json pins the exact decision version and rule you expect the adapter to apply. The decision version and rule identifiers appear in the JSON verdict of mneme check --json, shown in the CI-only setup. The plugin’s README file describes every field; follow it rather than this summary, because main moves.

  


  

    
What is and isn’t enforced

    
    
      
  • Enforced, with the released package: the CI check, on every file a pull request adds or modifies.
    • 
      
  • Experimental adapter, when installed from source: new .py file writes and existing .py file edits in the terminal CLI, for FORBID_LITERAL rules only.
    • 
      
  • Not intercepted by the adapter: overwriting an existing file, non-Python files, shell commands, MCP and custom tools, deletion and rename. It has no end-of-turn check.
    • 
      
  • Fails open: when the adapter can’t evaluate a change, OpenCode proceeds.
    • 
      
  • Not race-resistant: a file created or swapped between the check and the write is a known bypass.
    • 
      
  • Not covered: the OpenCode editor extension and desktop app.
    • 
    

  


  

    
Troubleshooting

    
The adapter prints Mneme NOT_PROTECTED

    
Its setup is invalid, most often the authorityPath or the pinned identifiers, and it lets the change through. Check the file against the plugin’s README.md.

    
The adapter prints Mneme WARN: warn_mode_violation

    
It is in warn mode, which reports and never blocks. The warning is a diagnostic, not protection.

    
CI fails at the memory check

    
An ADR changed without a re-import. The CI-only setup covers it.
