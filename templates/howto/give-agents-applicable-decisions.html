Goal

An agent writes better code when it knows the rules for the file it's editing. Mneme can look up the decisions that match a task or a path. Claude Code reaches that lookup through the plugin's /mneme:context command. Codex, or any other agent that speaks MCP (Model Context Protocol), reaches it through Mneme's local MCP server.

Lookup only informs the agent. Enforcement stays with the hook and CI checks from guides 2 and 4.

Prerequisites

  • ADR-012 in docs/adr/ and imported into .mneme/project_memory.json, as in Guide 1.
  • Mneme 0.9.2 with the optional MCP runtime:
pipx install "mneme-hq[mcp]==0.9.2"
  • For the Claude Code path, the plugin loaded as in Guide 2.

Configure

1. Give each decision a scope word that appears in your paths

Lookup matches words in the query against each decision's scope, text and rationale. A match on the scope counts most. ADR-012 uses scope: handlers because every file it governs lives under app/handlers/:


    
Words shorter than four letters never match, so api can't work as a scope. The troubleshooting section shows what happens.


    
2. Register the MCP server with your agent

    
The server runs on your machine and talks over standard input and output. Agents keep MCP servers in their own config files, each with its own format. This is the process definition to put there:

    
{
  "mcpServers": {
    "mneme": {
      "command": "mneme",
      "args": ["decision-mcp", "--proposals", ".mneme/decision_proposals.json", "--adr-dir", "docs/adr"]
    }
  }
}

    
--adr-dir loads your ADRs as the decisions the server returns. We tested the server with a generic MCP client, shown below, not inside a specific agent. The MCP server reference covers every option.

  


  

    
Run

    
Claude Code: /mneme:context

    
Type /mneme:context with a description of the task. The command runs this lookup, which you can also run yourself:

    
mneme test_query --memory .mneme/project_memory.json --query "edit to app/handlers/invoices.py"


    
Any MCP host: decision.applicable_to

    
This small client starts the server the way an agent does and calls one tool. Save it as mcp_probe.py in the repository root:

    

    
python mcp_probe.py list
python mcp_probe.py decision.applicable_to \
  '{"paths": ["app/handlers/invoices.py"]}'

Troubleshooting

    
A lookup for a generic file name returns nothing

    
A bare file name like utils.py shares no words with any decision:

    
mneme test_query --memory .mneme/project_memory.json --query "edit to utils.py"

    

    
Use the full path, or describe the task in words that appear in the decision.


    
A scope like api never matches

    
Here ADR-012 governs app/api/ with scope: api. The path contains the scope, but three letters is below the four-letter minimum:

    

    
Pick a scope word of four letters or more that appears in the governed paths, such as handlers or routes.


    
The MCP server won't start

    

    
The server refuses to start when --adr-dir is missing, empty, or holds an ADR it can't parse. Fix the path or the ADR. Leave --adr-dir out to run with proposals only.

  


  

    
Limits

    
    
      
  • Lookup gives the agent context. It doesn't stop anything. Keep the hook and the CI check in place.
    • 
      
  • Matching is by shared words, not meaning. A task phrased in words the decision doesn't use won't find it.
    • 
      
  • The MCP server is local and stdio-only. It has no HTTP endpoint and no authentication.
    • 
      
  • Over MCP an agent can read decisions and submit proposals. It can't accept a proposal or change enforcement; people review proposals with the CLI.
