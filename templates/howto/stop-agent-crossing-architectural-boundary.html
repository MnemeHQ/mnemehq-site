Goal

A pull request check catches a forbidden import after the agent wrote it, and someone still has to send the work back. A hook catches it while the agent is still working on the change. A hook is a command Claude Code runs at fixed points; the Mneme plugin registers one that runs before every file edit and shell command, at session start, and each time the agent finishes a turn.

The hook runs in strict mode by default: when a change breaks a decision, it exits with code 2, which Claude Code treats as “block this change”. The example decision is an architecture decision record (ADR), ADR-012, that bans importing the database client in request handlers.

  • A git repository with ADR-012 imported into the memory file, .mneme/project_memory.json, where Mneme stores your decisions. This is the ADR:

    
    
      
  • Import it with mneme adr import docs/adr --memory .mneme/project_memory.json --apply. Turn an ADR into an enforceable decision explains the file line by line; Install Mneme and activate your first protection covers installing Mneme.

  • Claude Code. The plugin isn't in the Claude Code marketplace yet, so you load it from a checkout of the Mneme repository. The Claude Code integration page lists what the plugin contains.

Configure

    
1. Get the plugin at the release tag

    
git clone --branch v0.10.0 --depth 1 https://github.com/MnemeHQ/mneme mneme-src

    
2. Start Claude Code with the plugin, from your repository root

    
claude --plugin-dir ./mneme-src/integrations/claude-code-plugin

    
Keep the default strict mode. Warn mode (MNEME_HOOK_MODE=warn) stops the hook from blocking edits, and Claude Code then shows neither you nor the agent why an edit broke a decision. See Troubleshooting.

  


  

    
Run

    
Ask Claude Code for a change that breaks ADR-012, for example: “Add a list_invoices handler in app/handlers/invoices.py that queries the invoices table with get_connection from app.db.client.”

    
When the agent goes to write the file, Claude Code sends the hook an event: a JSON description of the tool call (Write here; the hook also checks Edit and MultiEdit). This one is shortened to relative paths; Claude Code sends absolute ones.

    

    
To see the hook's answer without running an agent, save the event as events/write-direct-import.json and pipe it to the hook from the repository root:

    
mneme-hook < events/write-direct-import.json

  


  

    
Expected result

    
The hook exits with code 2 and prints:

    

    
Claude Code treats exit code 2 from this hook as a block. The file isn't written, and the agent receives that text as feedback. A write that calls the repository instead exits 0 with no output, so the agent can carry on.

    
Shell writes

    
The hook also reads shell commands. A single command of the form cat > app/handlers/invoices.py <<'PY', with a quoted delimiter and nothing else in the command, is blocked the same way. Its event, events/bash-heredoc.json:

    

    
mneme-hook < events/bash-heredoc.json

    

    
Other shell writes can't be checked before they run: echo >, tee, sed -i, an unquoted heredoc, a heredoc chained after another command, or a script such as python scripts/gen_invoices.py. The hook can't work out in advance what they will write, so it lets them through. Its note says the command might change files (POTENTIALLY_MUTATING) and that the end-of-turn check still applies:

    

    
The end-of-turn check catches them instead. Here is the script the agent might run, scripts/gen_invoices.py:

    

    
At session start the hook records the state of the repository, its baseline. When the agent finishes its turn, Claude Code sends a Stop event, and the hook checks the content each file gained since the baseline. Replayed in order:

    
mneme-hook < events/session-start.json
python scripts/gen_invoices.py
mneme-hook < events/stop.json

    
The Stop check blocks the end of the turn and sends the agent back with the violation:

    

  


  

    
Evidence

    
Every FAIL block names the decision (ADR-012), the matched text, and the path selector that made the rule apply. Behind the hook is the same mneme check command you can run yourself. To keep a machine-readable record of a file's state, run it with --json:

    
mneme check --memory .mneme/project_memory.json \
  --input app/handlers/invoices.py \
  --target-path app/handlers/invoices.py \
  --query "edit to app/handlers/invoices.py" \
  --json

    

  


  

    
Troubleshooting

    
Nothing is ever blocked, and the hook prints nothing

    
The hook didn't find a memory file. It looks for .mneme/project_memory.json in the session's working directory and each parent directory, or at the path in MNEME_MEMORY. With no memory file it allows every change silently:

    
MNEME_MEMORY=missing.json mneme-hook < events/write-direct-import.json

    

    
Start Claude Code from the repository root, or set MNEME_MEMORY.


    
not inside a git work tree

    

    
The end-of-turn check compares against git. Run Claude Code inside a git repository. Checks before each write still work without git.


    
Edits that break ADR-012 go through, with no message

    
MNEME_HOOK_MODE=warn is set. Check echo $MNEME_HOOK_MODE in the shell that started Claude Code, and the plugin's mode option, which sets the same thing. In warn mode the hook doesn't block; it answers defer, which hands the edit to Claude Code's normal permission flow. Claude Code doesn't show the violation the hook attaches as the reason:

    

    
Claude Code ignores that reason, so neither the agent nor you sees it. Only the end-of-turn check reaches the agent in warn mode. Unset the variable to go back to strict mode, and use mneme check or the CI check to collect findings instead.

  


  

    
Limits

    
    
      
  • The hook fails open: if a mneme check call crashes, takes longer than 10 seconds, or can't complete its evaluation (INCOMPLETE), the hook allows the change without telling the agent. Its notes go to Claude Code's debug log only.
    • 
      
  • Shell writes other than that single cat heredoc form are checked only when the agent finishes its turn, after the file exists. The hook then keeps the agent working and feeds back the violation. It doesn't undo the write.
    • 
      
  • The rule matches exact text, so import app.db.client as db isn't caught by this ADR. See Turn an ADR into an enforceable decision.
    • 
      
  • Other agents get different coverage. Codex CLI checks apply_patch add and update operations before they run, and audits each changed file as a whole when the agent stops. Kiro checks its native write tools only, with no shell or end-of-turn checks.
