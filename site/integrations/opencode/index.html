OpenCode Governance

OpenCode runs an open-source coding agent across the terminal, an IDE extension, and a desktop app. Mneme ships an experimental adapter for the terminal CLI: it checks Python file writes and edits against recorded architectural decisions before they land. It covers one surface and two Python operations, it is not race-resistant, and it is not a supported integration. This page describes what ships and what does not.

OpenCode is a multi-surface coding agent

OpenCode is an open-source coding agent that does not live in a single place. It runs in the terminal, as an IDE extension, and as a desktop app, supports parallel agent sessions on the same project, and connects to a large range of model providers. It is, in the vocabulary we use for this stack, a harness: the execution layer that coordinates tool calls, state, and the agent loop across more than one surface.

That breadth is exactly why governance matters here. The more surfaces an agent acts through, the more places an architectural decision can quietly fail to apply. A rule enforced in the terminal but not in the desktop app is not a rule.

OpenCode coordinates execution across surfaces. Mneme’s adapter attaches to the terminal CLI only. Coverage there does not imply coverage in the IDE extension or the desktop app.

The integration surface: OpenCode's tool hook

OpenCode exposes a plugin system with an execute.before hook at the point where a tool is about to mutate files. The Mneme adapter registers there, runs mneme check against the team’s recorded decisions, and throws on a trusted literal violation so the host refuses the change. What ships is narrower than the hook surface: two Python operations on the terminal CLI.

Modes: strict and warn

In strict mode a trusted literal violation blocks: the plugin throws and the host refuses the write or edit. In warn mode the same evaluation proceeds and the plugin prints Mneme WARN: warn_mode_violation. The warning is a diagnostic, not protection. There is no advisory check after a change lands, and no Stop or session-boundary pass.

Compaction: evaluated, closed as NULL

OpenCode documents compaction hooks designed to preserve task state, decisions, modified files, and multi-agent dependencies across longer sessions. We ran a controlled experiment injecting governance summaries through compaction; it completed with a NULL verdict (no measurable effect on outcomes) and was closed evidence-only, without adoption. The distinction at the heart of Mneme still stands: the difference between remembering a decision and enforcing it. But we will not claim a compaction-based context capability that validation did not support.

Where this sits in the stack

OpenCode is the harness; Mneme is the decision and control layer that runs alongside it. They are different layers of the runtime stack and they compose: OpenCode decides how the agent executes, and Mneme decides whether the resulting change respects the architecture. That composition is validated on other surfaces (Claude Code, Claude Agent SDK, Google Antigravity) and implemented here for the terminal CLI, where it remains experimental. The full argument for why a capable harness still needs this layer is in Harness Engineering Still Needs Governance.

Status: experimental. The adapter ships on main but is not a supported integration. Race resistance is NOT_ESTABLISHED: a target substituted between evaluation and the host write is a documented bypass. The host supplies no callID, so the evidence claim is none. If you need enforcement now, use a supported native integration or a CI gate.

Frequently asked questions

What is OpenCode?+
OpenCode is an open-source coding agent that runs in the terminal, as an IDE extension, and as a desktop app. It supports parallel agent sessions on the same project, works with a large number of model providers, and exposes a plugin system with hooks for tool execution and session lifecycle events.
How does Mneme integrate with OpenCode?+
Mneme's OpenCode adapter registers on the execute.before tool hook in the terminal CLI and gates two Python operations: writing a new file and editing an existing one. It runs the canonical mneme check against recorded FORBID_LITERAL decisions and throws on a trusted violation in strict mode. It is experimental; other tools and file types are not covered.
Would this be advisory or blocking?+
Both modes exist. strict blocks a trusted literal violation by throwing, so the host refuses the change. warn allows it and prints Mneme WARN: warn_mode_violation. Neither mode is race-resistant, and unsupported tools are not intercepted.
Why govern OpenCode if it already runs the agent well?+
Running the agent well is execution; keeping the architecture coherent is governance. OpenCode coordinates tool calls, parallel sessions, and long-running work across the terminal, IDE, and desktop. Mneme enforces the architectural decisions those surfaces have no opinion about, so the same constraints hold no matter which surface the agent is acting through.
