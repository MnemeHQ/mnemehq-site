Mneme + Kiro

PreToolUse Hook Integration & Architectural Governance

Overview

Kiro executes file mutations through tool calls that can be intercepted via client-side hook architectures. By configuring Mneme HQ as a PreToolUse hook handler, you can ensure that every write operation emitted by Kiro is evaluated against your project's authoritative decision memory before the file system is modified.

Enforcement Scope Boundary: Kiro currently implements PreToolUse prevention only. Session baseline capture (SessionStart) and post-session delta auditing (Stop) are deferred in this integration tier.

Hook Configuration

Configure the hook inside your Kiro settings or project configuration file using the standard schema:

{
  "version": "v1",
  "hooks": [
    {
      "trigger": "PreToolUse",
      "matcher": "^(fs_write|fsWrite|write|fs_append)$",
      "command": "mneme-kiro-hook",
      "timeout": 30
    }
  ]
}

Behavior & Exit Codes

The hook evaluates the proposed payload against compiled constraints and communicates via exit codes:

  • Strict Mode (Exit 2): Emits violations to stderr and blocks the mutation immediately.
  • Warn Mode (Exit 0): Emits a non-blocking warning to stdout and permits the mutation.
  • Operational Failure (Exit 0): Emits a visible notice if the decision corpus cannot be read.

Known Limitations

  • CLI v2 Behavior: CLI v2 execution loops ignore blocking exit codes and write anyway; strict enforcement is unsupported on CLI v2.
  • MCP Namespaced Tools: Kiro's namespaced tool format (@server/tool) is not natively mapped by the current adapter tier.
  • IDE 1.x Support: IDE-level integration surfaces are pending live validation and are not currently claimed.
