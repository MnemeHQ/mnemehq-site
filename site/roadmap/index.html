NowP0 · current focus

External validation and adoption

The current phase is not about maximizing integration count. It is about demonstrating that recorded architectural decisions change what AI coding agents actually build without materially reducing functional completion.

Design partners and real repositories

Measure first-attempt architectural compliance, functional completion, scope expansion, setup friction, and continued use on real projects.

Architecture Audit

Use the Audit Workspace to identify enforceable, partial, and guidance-only decisions and turn that assessment into pilot evidence.

Architecture-compliance benchmark

Build externally legible comparisons with frozen fixtures, deterministic scoring, and explicit treatment/control boundaries.

Evidence over breadth

A design-partner result or reproducible benchmark carries more weight than another unvalidated adapter.

NextP1

Strengthen the review and ingestion surfaces

Next work should make the existing enforcement layer easier to apply, not create a parallel policy system.

Architecture Review Skill

Evolve the existing Claude Code Mneme Skill into a clearer executable review workflow over /mneme:context, /mneme:check, /mneme:record, and /mneme:review.

Confluence ADR ingestion

Reduce adoption friction for teams whose architectural decisions already live in Confluence while keeping ingestion separate from enforcement semantics.

Migration-aware Audit

Extend the Audit workflow for legacy/target coexistence and path-scoped decisions rather than creating a separate migration product.

Deep Agents capability POC

Validate the filesystem mutation seam and nested-agent propagation before making any support claim.

Architecture Review boundary: the Skill is an interface over Mneme retrieval and deterministic enforcement. It does not become a second policy engine.
ResearchP2 · evidence first

Test the emerging harness layer

These are research surfaces, not integration claims. Each must prove a useful control boundary before promotion.

Slack Code / shared multi-agent constraints

Investigate whether one project architectural contract can govern multiple coding agents and sessions inside a shared harness.

AWS AgentCore benchmark

Use AgentCore as a controlled execution substrate for architecture-compliance benchmarking before considering deeper integration.

Salesforce Skills interoperability

Test whether Mneme adds project-specific architecture compliance on top of Salesforce domain Skills. This is not a Claudeforce integration claim.

Claude Managed Agents revisit

Revisit the current PARTIAL result only when Anthropic exposes current workspace bytes, a filesystem-local evaluator, or a blocking completion boundary.

Deferred

Wait for user pull

Broader platform work remains intentionally behind external validation.

  • EventCatalog graph enrichment beyond the validated retrieval-only boundary.
  • Team and org policy synchronization, shared policy packs, and cross-repo governance.
  • Generic hosted MCP / HTTP control plane and broad SaaS administration.
  • Higher-level policy DSL beyond the current typed-rule path.
  • Deeper integrations without a reliable mutation or verification seam.
Shipped foundation

What this roadmap builds on

The roadmap assumes the current shipped foundation: typed and path-scoped enforcement, governability assessment, ADR lifecycle analysis, and maintained integration adapters with evidence.

  • Native: Claude Code, Claude Agent SDK, Google Antigravity, Codex CLI, LangChain/LangGraph, and Kiro CLI v3.
  • Validated compatibility: Paperclip.
  • Experimental: Hermes Agent; OpenCode remains incomplete.
  • Evidence-only: Claude Managed Agents PARTIAL.
  • EventCatalog retrieval-only ADR ingestion and effectiveness validation.
  • Architecture Audit Workspace over the authoritative Mneme governability API.

Support status is evidence-based and can change independently of roadmap priority. See Integrations for current public support claims.
