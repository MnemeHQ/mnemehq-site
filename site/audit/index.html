What the audit tells you

Decisions discovered

ADRs, CLAUDE.md, AGENTS.md, architecture docs, config files — every source of architectural intent in the repository.

Protection classified

Each decision rated: Protected, Mneme-ready, Requires modelling, or Guidance.

Proposed Mneme guardrails

See the exact deterministic Mneme guardrail where one exists (e.g., FORBID_LITERAL).

Protection gaps

Decisions that aren't yet protected — with specific next steps: modeling needed, or guardrail identified ready for CI/CD integration.

Exportable report

Download the full audit as Markdown or JSON to share with your team or design partners.

Designed for design partners

This audit is the artifact you send after a design-partner call — concrete evidence of where their architecture is ambiguous to AI agents.

Persistent pilot workflow

M1 adds durable project identity so the audit is no longer a one-off report. Teams can now track protection improvement over time.

1 Audit

Run an Architecture Protection audit against any repository. Get baseline protection metrics and identified guardrails.

2 Save Baseline

Persist the audit as a project baseline with repository URL, commit SHA, Mneme version, and timestamp. Baseline is immutable.

3 Improve Protection

Implement Mneme-ready guardrails in CI/CD. Address "Requires modelling" gaps. Each change raises the protection percentage.

4 Re-audit

Run a re-audit against the new repository state. Creates a new immutable snapshot linked to the same project.

5 Compare

Baseline vs. latest comparison shows: Architecture Protection delta (e.g., 20% → 60%), newly Protected decisions, new guardrails, regressions, added/removed decisions. All computed server-side from canonical P1.2 evidence.

Illustrative example: a team starting at 20% protection (1 of 5 decisions Protected) implements 2 Mneme-ready guardrails and reaches 60% (3 of 5 Protected). Results vary by repository.

The important distinction

Don't say:

"Mneme found architectural drift."

The audit asks:

"Can this architectural intent be deterministically protected from AI-generated drift?"

You don't have generalized drift detection yet. The audit is valuable precisely because it answers a narrower, answerable question — and that answer is what Mneme actually does today.

Want to see what the answer looks like before running it? The ADR compiler demo takes one written decision and shows it becoming an executable constraint, and how AI coding agents use ADRs explains the ignored, advisory, and enforced progression the audit is measuring against.
